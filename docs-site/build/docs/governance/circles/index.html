Holacracy Circles

Circles are teams organized around purpose, not hierarchy. Multiple circles can nest, with representatives connecting them.

Circle Structure​

Every circle has these core roles:

RolePurpose
Circle LeadOwns circle evolution, fills vacancies, breaks ties in governance
FacilitatorRuns Tactical and Governance meetings
SecretaryRecords decisions, maintains records, publishes minutes
Circle RepRepresents circle in parent circle

Domain Roles​

Specialized roles focused on specific work:

  • Documentation Lead — owns docs site
  • API Developer — owns API design
  • DevOps — owns infrastructure
  • etc.

Each role has a purpose (why), domain (what it owns), and accountabilities (responsibilities).

Sub-circles​

Circles can contain sub-circles:

General Company Circle
├── Operations Circle
│   ├── Documentation Sub-circle
│   └── Infrastructure Sub-circle
└── R&D Circle

The Circle Rep from each sub-circle participates in the parent circle's meetings.

Example: Documentation Circle Decision Context​

Created from: MYA-5, MYA-127 — AI Intelligence + Onboarding (2026-05-27)

Problem: No single team owned information flow. New agents scattered search across docs, Slack, code comments. Knowledge captured but not organized.

Decision: Create Documentation circle to centralize ownership of onboarding, knowledge architecture, and documentation freshness.

Core roles established:

  • Doc Lead: owns docs site tooling and architecture
  • Technical Writer: produces API/feature documentation
  • Onboarding Designer: creates playbooks for new role setup
  • Knowledge Curator: ingests AI research, produces daily digest

Design logic: Each role has explicit accountability + domain. Tensions surface weekly in Tactical meetings. Governance decisions recorded with this circle context.

Related: MYA-172 (Knowledge Graph runbook), MYA-173 (decision context in docs)

Governance Meetings​

Run bi-weekly to:

  • Process governance tensions
  • Add/remove/modify roles
  • Create new policies
  • Update circle purpose or domain

Tactical Meetings​

Run weekly to:

  • Process operational tensions
  • Assign work to roles
  • Discuss blockers
  • Sync on progress
